# Deterministic harness synthesis

The generator separates three questions:

1. **Entry** — which real API/callback receives external bytes?
2. **Context** — what must be initialized, allocated, reset, and released?
3. **Mutation** — which values may vary without breaking the contract?

P0 supports deterministic C/C++ harnesses for independent functions with a
byte buffer and logical length. Everything else is either `adaptable` (user
wrapper/context required) or `blocked`.

## Pipeline

```text
S1 collect candidates from compdb + analysis
S2 join AST declaration/definition with IR facts
S3 classify argument roles with evidence
S4 recover explicit setup/teardown/wrapper context
S5 establish buffer/length/capacity contract
S6 resolve HAL/ABI platform boundaries
S7 reject unknown critical constraints
S8 canonicalize harness_plan.json (no code yet)
S9 emit C/C++ source and host-build
S10 validate compile → link → seed → reach → input use → stability
S11 promote to fuzzable or emit exact blocking reason
```

S1–S8 are side-effect-free except for writing canonical plans. S9–S11 may create
files and execute binaries. A failed gate never rewrites an earlier plan.

## Role inference

Supported roles:

| Role | Harness source |
|---|---|
| `FUZZ_BYTES` | Engine input pointer (read-only). |
| `FUZZ_BYTES_MUTABLE` | Harness-owned copy of input bytes. |
| `LOGICAL_LENGTH` | `size`, after an exact-width guard and explicit cast. |
| `CAPACITY` | `size` only with an explicit user contract; otherwise adaptable. |
| `OUTPUT_BUFFER` | Not synthesized in P0; wrapper required. |
| `CONTEXT` | Not synthesized; wrapper/factory required. |
| `CONFIG` | No automatic value source; wrapper required. |
| `UNKNOWN` | Prevents automatic synthesis. |

Evidence is collected from:

1. parameter type and `const`;
2. AST pointer dereference/index use;
3. LLVM IR `memory_read`, `memory_write`, `indexed`, `compare`,
   `compare_constant:<n>`, `branch`, `loop_bound`, `allocation_size`,
   `passed_to_call`, `may_escape`, `data_dependent`, and conservative
   interprocedural argument-use propagation;
4. caller/unit-test evidence (future P1);
5. explicit `targets.args` user contract.

No decision is based on the name `len` alone. An exact
`const uint8_t * + size_t` pair can be a ready candidate from type evidence even
when IR is unavailable, but the plan records `AST_ONLY`/fallback status and the
input-use gate still runs.

## Generated C example

```c
/* GENERATED by fuzzfw; do not edit. */
#include <stddef.h>
#include <stdint.h>
#include <limits.h>
#include <stdlib.h>
#include <string.h>
#include "include/sensor.h"

int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) {
    if (size > 4096) return 0;
    if (size > SIZE_MAX) return 0;
    (void)sensor_decode(data, size);
    return 0;
}
```

For a mutable pointer the generator allocates and copies:

```c
uint8_t *copy = NULL;
if (size > 0) {
    copy = (uint8_t *)malloc(size);
    if (copy == NULL) return 0;
    memcpy(copy, data, size);
} else {
    copy = (uint8_t *)malloc(1);
    if (copy == NULL) return 0;
}
(void)sensor_decode_mut(copy, size);
free(copy);
```

The read-only path similarly uses an exact-size heap copy when
`harness.copy_input=true`:

```c
const uint8_t *input = malloc(size ? size : 1);
memcpy((void *)input, data, size);
target(input, size);
free((void *)input);
```

This makes reads past `size` visible to ASan even when the fuzzer's source buffer
has a larger capacity. The copy is allowed only because the plan records that
ownership stays with the caller and that the target does not retain the
pointer. Otherwise the target is
`adaptable` and needs a user wrapper.

## Length width and truncation

For `int parse(const uint8_t *p, uint16_t n)`, the harness rejects
`size > UINT16_MAX`; it never writes `n = (uint16_t)size`. The same rule applies
to signed and 32-bit lengths. The maximum input size is also an explicit engine
limit, not a guessed parser rule.

## Validation gates

| Gate | Evidence | Failure |
|---|---|---|
| G0 static contract | roles, header, adapters, ABI | blocked/adaptable |
| G1 compile | exact header, host profile | `E_HARNESS_BUILD` |
| G2 link | original objects + adapters | `E_LINK_GRAPH_UNKNOWN` |
| G3 seed smoke | empty/seed/boundary inputs | `E_HARNESS_SMOKE` |
| G4 reachability | coverage callback sees entry symbol | `E_ENTRY_UNREACHED` |
| G5 input use | IR read/call evidence or coverage sensitivity | warning/unknown |
| G6 context | explicit setup/teardown/wrapper provenance | adaptable |
| G7 stability | repeated isolated coverage/exit and same-process persistent reset probe | `E_STATE_LEAK` |
| G8 reproduction | independent replay attempts | `flaky`/`non_reproducing` |

Coverage equality alone is not proof that input was ignored; G5 records
`weak_sensitivity` or `unknown` when direct memory-read observation is absent.

## Determinism

- `harness_id` is SHA-256 of canonical `harness_plan.json`.
- JSON keys are sorted, role/constraint order is normalized, and paths are
  project-relative where possible.
- Harness source has a fixed header, no timestamps, and no random names.
- The same plan and generator version must emit byte-identical source.

## Adapter rules

An adapter is a reviewed model of a hardware boundary, not a universal fake. It
must declare prototype, effects, valid context, nondeterminism, and limitations.
A prototype mismatch or unknown effect blocks the target. A `return 0` body is
not accepted as an input source; status-only models are allowed only when the
contract explicitly says so.

## C++ object lifetime

P0 does not create arbitrary C++ objects. A member-function target is supported
only with an explicit, validated factory:

```toml
[[targets]]
name = "parser_feed"
symbol = "Parser::feed"
header = "include/parser.hpp"
factory = "Parser::create_default"
```

The generator emits one of:

```cpp
// factory returns Parser by value
auto object = Parser::create_default();
(void)object.feed(data, size);

// factory returns std::unique_ptr<Parser>
auto object = Parser::create_unique();
(void)object->feed(data, size);

// factory returns RawParser* and destroy is configured
auto *object = RawParser::create();
if (object == nullptr) return 0;
(void)object->feed(data, size);
RawParser::destroy(object);
```

Factory class, return type, staticness, and destroy pointer argument are checked
against the AST. A raw-pointer factory without `destroy` is blocked. A
non-static member factory, reference return, or mismatched class is blocked. If
the factory cannot be proven, use the user wrapper path.

## Output buffers and capacity

Explicit output buffers are supported for parsers that write into caller-owned
storage:

```toml
output_bytes = 64
args = ["FUZZ_BYTES", "LOGICAL_LENGTH", "OUTPUT_BUFFER", "CAPACITY"]
```

The harness allocates a zeroed, exact-size output buffer, passes the configured
capacity, frees it after the call, and lets ASan catch writes past the capacity.
The generator does not guess output arguments automatically; this role requires
an explicit `args` contract.

## Sanitizer profiles

The default profile is ASan + UBSan. For length/overflow-heavy parsers,
`integer`, `implicit-conversion`, `local-bounds`, `pointer-overflow`, and
`object-size` can be enabled explicitly. They are opt-in because unsigned
wrapping is sometimes intentional and would otherwise create noise.

## Constant dictionary

The planner extracts integer/character/string constants from the target and
comparison facts into a small deterministic dictionary. Build writes it as
`dictionary.txt` and the engine adapter passes it to libFuzzer (`-dict=`) or
honggfuzz (`--dict`). This helps command IDs, magic values, and parser
constants without inventing a protocol grammar.

## Sequence / framed input

For stateful protocols, `input = "length_prefixed"` treats the fuzz input as a
sequence of frames:

```text
u32_le length | payload | u32_le length | payload | ...
```

Each valid frame gets its own exact-size copy and target call; setup/context/
factory are constructed once, event hooks run per frame, and the frame count is
bounded by `max_frames`. Truncated or oversized frames stop the sequence. The
target still receives the original frame bytes; no protocol semantics are
invented.

`state_probe` observes the machine after each call. With a context it must be
`int(context *)`; without one it must be `int(void)`. The observed value is
folded into a deterministic state hash alongside the frame index, and the
replay report records `frames` and `state_hash`. These are observations only;
they do not invent transitions.

`frame_reset` is an explicit per-frame cleanup contract. It must be
`void(void)` or `void(context *)` and is called after the probe and events for
each frame. The whole-input `context.reset` remains the teardown reset.

## C context objects

Context pointers are not raw zeroed memory. A target can declare an explicit
context lifecycle:

```toml
[targets.context]
kind = "opaque"
size = 16
init = "parser_context_init"
reset = "parser_context_reset"
arg = 0
```

The harness allocates the configured size, calls the declared init, passes the
typed context pointer, calls reset/destroy if present, and frees it. Init/reset/
destroy signatures and argument indices are checked against the AST. A context
that cannot be proven is blocked or requires a wrapper.

## Event models (DMA / ISR / RTOS)

Event boundaries are not simulated by an arbitrary scheduler. The target must
use an approved adapter contract and, where needed, explicit event hooks:

```toml
[[targets]]
name = "dma_process"
symbol = "dma_process"
header = "include/dma.h"

[[targets.events]]
symbol = "dma_event_flush"
phase = "before"
```

```json
{
  "event_model": "dma_completion",
  "completion": "deferred",
  "ownership": "caller"
}
```

The generated harness binds a read-only input stream before the target, calls
`before` hooks, invokes the target, calls `after` hooks, and clears the stream.
Adapters read bytes with `fuzzfw_input_read()`. DMA requires
`event_model=dma_completion`; deferred completion requires at least one event
hook. ISR requires an `isr_callback` adapter or event hook. RTOS requires an
`rtos_event` adapter and event hook. Direct MMIO and inline assembly remain
blocked. No real interrupt timing, scheduler, or DMA engine is claimed.

## Persistent reset

Before a target is allowed into a persistent engine run, the self-test repeats
one non-empty input three times **inside the same process**. The first call is
allowed to perform one-time initialization; the warm calls must have identical
coverage and entry-hit results. Any difference reports `E_STATE_LEAK` and keeps
the target out of `fuzzable` state. This catches static counters/state that
would contaminate coverage and findings.

## Explicit wrapper escape hatch

When automatic synthesis refuses a target, keep product code untouched and
write a small wrapper:

```c
void fuzzfw_target(const uint8_t *data, size_t size) {
    firmware_test_init();
    app_on_rx(data, size);
    firmware_test_shutdown();
}
```

The wrapper is a supported product path. It is never exempt from the build,
reachability, stability, and replay gates.
